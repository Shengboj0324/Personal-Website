THE QUESTION

Admissions, financial aid, and transfer pathways all depend on specific information. At Athena AI Labs, I worked on an application that retrieves supporting material before constructing an answer, with checks for questions the available sources cannot support.

01

Connecting the whole application

I developed a SwiftUI interface, a Python API, and retrieval-augmented generation workflows for college-advising questions. Student-profile integration supported personalized recommendations, while document ingestion organized the information the system could consult.

02

Retrieval before generation

The published architecture combines keyword and vector retrieval, source-authority weighting, specialized question handling, and a cite-or-abstain check. Its language model formats the response; retrieved evidence supplies the factual basis. The distinction helps make the answer’s support inspectable.

03

Making the work inspectable

I published CollegeAdvisor-RAG on Hugging Face with architecture notes and usage instructions. A model listing is also available on Kaggle. The portfolio focuses on the implemented retrieval and citation design; benchmark claims in a model card should not be read as a guarantee for every admissions question.

INSIDE THE ENGINEERING

Retrieval does the factual work.

  1. 01

    Two routes to the evidence

    BM25 keyword retrieval captures exact names and terms, while dense retrieval finds passages with related meaning. Five ChromaDB collections organize the knowledge base. Combining these routes helps match both a specific college name and a less precisely worded question.

  2. 02

    Check the question and the source

    Source-authority weighting and specialized question handlers guide how retrieved material is used. A cite-or-abstain check keeps insufficient evidence visible rather than forcing every question into a confident answer. Student context enters through the application and API.

  3. 03

    A smaller model, a narrower job

    The published architecture uses a LoRA-adapted TinyLlama 1.1B model for response formatting. The retrieved evidence supplies factual content. Keeping those responsibilities separate makes it easier to inspect whether an answer is supported by its citations.

Architecture details follow the published model card. They describe the system’s design, not a guarantee that every retrieved fact is current or every answer is correct.
