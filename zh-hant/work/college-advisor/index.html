問題的起點

入學、經濟援助和轉學途徑都取決於具體資訊。在 Athena AI Labs，我開發了一個應用程序，該應用程式在建立答案之前檢索支援材料，並檢查可用來源無法支援的問題。

01

連接整個應用程式

我開發了 SwiftUI 介面、Python API 和用於大學諮詢問題的檢索增強生成工作流程。學生檔案整合支援個人化推薦，而文件攝取則組織系統可以參考的資訊。

02

產生前檢索

所發布的體系結構結合了關鍵字和向量檢索、來源權威加權、專門問題處理以及引用或棄權檢查。它的语言模型格式化响应；检索到的证据提供了事实依据。這種區別有助於使答案的支持變得可檢查。

03

使工作可檢查

我在 Hugging Face 上發表了 CollegeAdvisor-RAG，其中包含架構註釋和使用說明。 Kaggle 上也提供了模型清單。該組合重點關注已實施的檢索和引文設計；模型卡中的基準要求不應被視為每個招生問題的保證。

技術實作

檢索進行事實工作。

  1. 01

    獲取證據的兩條途徑

    BM25關鍵字檢索捕捉準確的名稱和術語，而密集檢索則找到具有相關意義的段落。五個 ChromaDB 集合組織了知識庫。組合這些路線有助於匹配特定的大學名稱和措辭不太精確的問題。

  2. 02

    檢查問題與來源

    来源权威加权和专门的问题处理程序指导如何使用检索到的材料。引用或弃权检查可以保持证据不足，而不是强迫每个问题都给出自信的答案。学生上下文通过应用程序和 API 进入。

  3. 03

    較小的模型，較窄的工作

    所發表的架構使用適應LoRA的TinyLlama 1.1B模型來進行回應格式化。檢索到的證據提供了事實內容。將這些職責分開可以更輕鬆地檢查答案是否得到引用的支持。

架構細節遵循已發布的模型卡。它們描述了系統的設計，但不能保證每個檢索到的事實都是最新的或每個答案都是正確的。
