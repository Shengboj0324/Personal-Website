출발점이 된 질문

입학, 재정 지원, 편입 경로는 모두 구체적인 정보에 달려 있습니다. Athena AI Labs에서 저는 답변을 구성하기 전에 근거 자료를 먼저 검색하고, 이용 가능한 출처로 뒷받침할 수 없는 질문을 걸러내는 애플리케이션을 개발했습니다. 설계 목표는 소박하지만 엄격했습니다. 답변은 출처를 보여 주거나, 그럴 수 없다면 답하지 않아야 합니다.

5지식 컬렉션
조각검색 증강 생성
열려 있는모델 문서화
01

전체 애플리케이션 연결

저는 SwiftUI 인터페이스, Python API, 대학 상담 질문에 대한 검색 증강 생성 워크플로를 개발했습니다. 학생 프로필 통합은 개인화된 추천을 지원하는 동시에 문서 수집을 통해 시스템이 참조할 수 있는 정보를 정리했습니다.

02

서로 분리된 다섯 개의 컬렉션

지식 베이스는 다섯 개의 컬렉션으로 구성됩니다. 재정 지원 정책, 전공별 입학 요건, Common Data Set 수치, 편입 학점 인정 협정, 그리고 출처가 달린 답변 예시입니다. 이들을 분리해 두면 편입 학점에 관한 질문과 재정 지원에 관한 질문이 서로 다른 자료를 검색하게 되고, 결과가 어떤 종류의 출처에서 나왔는지도 밝힐 수 있습니다.

03

생성 전 검색

질문은 먼저 의미를 기준으로 이 컬렉션들과 대조되며, 공식 .edu 및 .gov 출처의 결과에는 다른 자료보다 높은 가중치가 부여됩니다. 공개된 설계 문서에는 키워드 검색도 설명되어 있지만, 여기서 설명하는 경로는 밀집(dense) 검색입니다. 언어 모델의 역할은 답을 문장으로 다듬는 것이고, 사실은 검색된 증거가 제공합니다.

04

인용하거나, 계산하거나, 답하지 않거나

어떤 질문은 애초에 텍스트로 답해서는 안 됩니다. 재정 지원과 비용 수치는 생성하지 않고 결정론적 계산기로 계산합니다. 법적 판단, 예측, 개인 취향을 묻는 질문은 검색 전에 걸러냅니다. 그리고 가장 좋은 증거도 약할 때는 답하지 않고 그 이유를 설명합니다. 프로젝트 자체 스트레스 테스트 세트에서는 대부분의 사례가 답변 거절로 처리되었습니다.

05

작업을 검사 가능하게 만들기

저는 CollegeAdvisor-RAG를 아키텍처 노트, 사용 안내와 함께 Hugging Face에 공개했습니다. Kaggle에서도 모델 목록을 볼 수 있습니다. 이 포트폴리오는 검색과 인용 설계에 초점을 맞추며, 모델 카드의 벤치마크 주장을 모든 입학 관련 질문에 대한 보장으로 읽어서는 안 됩니다.

기술 구현 살펴보기

검색은 사실에 근거한 작업을 수행합니다.

  1. 01

    의미로 검색하고, 권위로 순위를 매기다

    각 레코드는 임베딩되어 다섯 개의 ChromaDB 컬렉션 중 하나에 저장됩니다. 질문은 모든 컬렉션에서 후보를 검색하고, 권위 있는 도메인을 인용하는 후보는 상위 결과를 추리기 전에 가중치가 높아집니다. 최소 점수 기준이 약한 일치 결과를 답변에서 걸러냅니다.

  2. 02

    질문과 출처를 확인하세요

    전문 처리기가 재정 지원, 편입, 입학에 관한 질문을 알맞은 자료로 보냅니다. ‘인용하거나 답하지 않기’ 검사는 모든 질문에 억지로 확신에 찬 답을 내놓는 대신 증거가 부족하다는 사실을 드러냅니다. 학생 정보는 애플리케이션과 API를 통해 입력됩니다.

  3. 03

    더 작은 모델, 더 좁은 작업

    게시된 아키텍처는 응답 형식 지정을 위해 LoRA 적응 TinyLlama 1.1B 모델을 사용합니다. 검색된 증거는 사실적인 내용을 제공합니다. 이러한 책임을 별도로 유지하면 답변이 인용에 의해 뒷받침되는지 여부를 더 쉽게 검사할 수 있습니다.

아키텍처 세부 사항은 공개된 모델 카드와 제가 이 프로젝트에서 직접 한 작업을 바탕으로 합니다. 이는 시스템의 설계를 설명할 뿐, 검색된 모든 사실이 최신이거나 모든 답변이 정확하다는 보장이 아닙니다.

정직하게 밝히는 한계.

  • 평가는 프로젝트 자체에서 작성했습니다. 독립적인 벤치마크나 실제 사용자 기준 정확도 수치는 없습니다.
  • 인용은 답이 어디서 왔는지 보여 줍니다. 그 출처가 최신이라는 것까지 증명하지는 않습니다.
  • Hugging Face 릴리스는 호스팅된 자문 서비스가 아닌 문서화된 모델 아티팩트입니다.
단순화된 시스템 아키텍처

증거를 따르십시오.

  1. 01질문

    학생의 상황과 특정 정보 요구 사항.

  2. 02검색하다

    다섯 가지 출처 컬렉션을 검색하며 권위 있는 도메인에 가중치를 둡니다.

  3. 03검증

    전문적인 처리 및 인용 또는 기권 확인.

  4. 04대답하다

    인용을 뒷받침하는 형식의 답변입니다.
