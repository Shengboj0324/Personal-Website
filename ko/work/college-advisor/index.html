01

전체 애플리케이션 연결

저는 SwiftUI 인터페이스, Python API, 대학 상담 질문에 대한 검색 증강 생성 워크플로를 개발했습니다. 학생 프로필 통합은 개인화된 추천을 지원하는 동시에 문서 수집을 통해 시스템이 참조할 수 있는 정보를 정리했습니다.

02

생성 전 검색

게시된 아키텍처는 키워드 및 벡터 검색, 출처 권위 가중치, 전문 질문 처리, 인용 또는 기권 확인을 결합합니다. 해당 언어 모델은 응답 형식을 지정합니다. 검색된 증거는 사실적 근거를 제공합니다. 이러한 구별은 답변의 지원을 검사 가능하게 만드는 데 도움이 됩니다.

03

작업을 검사 가능하게 만들기

저는 아키텍처 노트와 사용 지침이 포함된 CollegeAdvisor-RAG를 Hugging Face에 게시했습니다. Kaggle에서도 모델 목록을 확인할 수 있습니다. 포트폴리오는 구현된 검색 및 인용 디자인에 중점을 둡니다. 모델 카드의 벤치마크 주장을 모든 입학 문제에 대한 보증으로 읽어서는 안 됩니다.

기술 구현 살펴보기

검색은 사실에 근거한 작업을 수행합니다.

  1. 01

    증거를 찾는 두 가지 경로

    BM25 키워드 검색은 정확한 이름과 용어를 포착하는 반면, 밀집 검색은 관련 의미가 있는 구절을 찾습니다. 5개의 ChromaDB 컬렉션이 지식 기반을 구성합니다. 이러한 경로를 결합하면 특정 대학 이름과 덜 정확한 단어의 질문을 모두 일치시키는 데 도움이 됩니다.

  2. 02

    질문과 출처를 확인하세요

    출처 권위 가중치 및 전문 질문 처리기는 검색된 자료가 사용되는 방법을 안내합니다. 인용 또는 기권 확인은 모든 질문에 확실한 답변을 강요하는 대신 불충분한 증거를 눈에 띄게 유지합니다. 학생 컨텍스트는 애플리케이션과 API를 통해 입력됩니다.

  3. 03

    더 작은 모델, 더 좁은 작업

    게시된 아키텍처는 응답 형식 지정을 위해 LoRA 적응 TinyLlama 1.1B 모델을 사용합니다. 검색된 증거는 사실적인 내용을 제공합니다. 이러한 책임을 별도로 유지하면 답변이 인용에 의해 뒷받침되는지 여부를 더 쉽게 검사할 수 있습니다.

아키텍처 세부정보는 게시된 모델 카드를 따릅니다. 이는 검색된 모든 사실이 최신이거나 모든 답변이 정확하다는 보장이 아니라 시스템 설계를 설명합니다.
