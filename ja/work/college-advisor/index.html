出発点となる問い

入学審査、学費援助、編入の道筋は、いずれも具体的な情報に左右されます。Athena AI Labs では、回答を組み立てる前に裏付けとなる資料を検索し、手元の情報源では裏付けられない質問を見分けるアプリケーションに取り組みました。設計の目標は控えめで、かつ厳格なものです。回答は、その出どころを示すか、回答を控えるかのどちらかでなければなりません。

5知識コレクション
ラグ検索拡張生成
オープンモデルのドキュメント
01

アプリケーション全体の接続

私は、ＳｗｉｆｔＵＩインターフェース、Ｐｙｔｈｏｎ ＡＰＩ、および大学へのアドバイス用の質問のための検索拡張生成ワークフローを開発した。学生プロファイルの統合により、パーソナライズされた推奨事項がサポートされる一方、ドキュメントの取り込みにより、システムが参照できる情報が整理されました。

02

五つのコレクションを分けて保持

知識ベースは五つのコレクションで構成されています。学費援助の方針、専攻ごとの入学要件、Common Data Set の数値、編入時の単位互換協定、そして出典付きの回答例です。これらを分けておくことで、編入単位に関する質問と学費援助に関する質問とで別の資料を検索でき、結果がどの種類の情報源から来たかを示すこともできます。

03

生成前の検索

質問はまず、意味に基づいてこれらのコレクションと照合されます。公式の .edu や .gov の情報源から得た結果は、他の資料より重く扱われます。公開されている設計文書にはキーワード検索についての記述もありますが、ここで説明しているのは密ベクトル検索の経路です。言語モデルの役割は答えの言い回しを整えることで、事実は検索された根拠が提供します。

04

引用か、計算か、回答を控えるか

そもそもテキストから答えるべきではない質問もあります。学費援助や費用の数値は、生成するのではなく、決定論的な計算機で算出します。法的判断、予測、個人の好みを求める質問は、検索の前に検出します。そして、最良の根拠でも弱い場合、システムは回答を控え、その理由を説明します。プロジェクト独自のストレステストでは、大半のケースが回答を控えることで処理されました。

05

ワークを検査可能にする

アーキテクチャの説明と使い方を添えて、CollegeAdvisor-RAG を Hugging Face で公開しました。Kaggle にもモデルを掲載しています。このポートフォリオでは、検索と引用の設計に焦点を当てています。モデルカードに記載されたベンチマークの主張は、あらゆる入試の質問に対する保証として読むべきではありません。

技術のしくみ

検索は事実に基づく作業を行う。

  1. 01

    意味で探し、信頼性で並べる

    各レコードは埋め込みに変換され、五つの ChromaDB コレクションのいずれかに保存されます。質問はすべてのコレクションから候補を検索し、信頼できるドメインを引用している候補は、上位の結果が選ばれる前にスコアが引き上げられます。最低スコアを設けることで、弱い一致は回答に入りません。

  2. 02

    質問と出典を確認する

    専用のハンドラーが、学費援助、編入、入学に関する質問を適切な資料に振り分けます。「出典を示すか、回答を控えるか」のチェックにより、すべての質問に無理に自信のある答えを出すのではなく、根拠の不足が見える形で残ります。学生の状況は、アプリケーションと API を通じて入力されます。

  3. 03

    モデルが小さくなると、ジョブの範囲が狭くなる

    公開されたアーキテクチャは、応答フォーマットにLoRAに適応したTinyLlama 1.1Bモデルを使用する。取得された証拠は事実の内容を提供します。これらの責任を分離しておくと、回答が引用によって裏付けられているかどうかを検査しやすくなります。

アーキテクチャの詳細は、公開されているモデルカードと、このプロジェクトでの私自身の作業に基づいています。これはシステムの設計を説明するもので、検索されたすべての事実が最新であることや、すべての回答が正しいことを保証するものではありません。
