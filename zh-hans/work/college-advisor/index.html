问题的起点

入学、经济援助和转学途径都取决于具体信息。在 Athena AI Labs，我开发了一个应用程序，该应用程序在构建答案之前检索支持材料，并检查可用来源无法支持的问题。

01

连接整个应用程序

我开发了 SwiftUI 界面、Python API 和用于大学咨询问题的检索增强生成工作流程。学生档案集成支持个性化推荐，而文档摄取则组织系统可以参考的信息。

02

生成前检索

所发布的体系结构结合了关键词和向量检索、来源权威加权、专门问题处理以及引用或弃权检查。它的语言模型格式化响应；检索到的证据提供了事实依据。这种区别有助于使答案的支持变得可检查。

03

使工作可检查

我在 Hugging Face 上发表了 CollegeAdvisor-RAG，其中包含架构注释和使用说明。 Kaggle 上还提供了模型列表。该组合重点关注已实施的检索和引文设计；模型卡中的基准要求不应被视为每个招生问题的保证。

技术实现

检索进行事实工作。

  1. 01

    获取证据的两条途径

    BM25关键词检索捕获准确的名称和术语，而密集检索则找到具有相关含义的段落。五个 ChromaDB 集合组织了知识库。组合这些路线有助于匹配特定的大学名称和措辞不太精确的问题。

  2. 02

    检查问题和来源

    来源权威加权和专门的问题处理程序指导如何使用检索到的材料。引用或弃权检查可以保持证据不足，而不是强迫每个问题都给出自信的答案。学生上下文通过应用程序和 API 进入。

  3. 03

    更小的模型，更窄的工作

    所发布的架构使用适应LoRA的TinyLlama 1.1B模型来进行响应格式化。检索到的证据提供了事实内容。将这些职责分开可以更轻松地检查答案是否得到引用的支持。

架构细节遵循已发布的模型卡。它们描述了系统的设计，但不能保证每个检索到的事实都是最新的或每个答案都是正确的。
